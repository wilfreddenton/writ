## Executive summary

The codebase is functionally healthy but carries a large, clearly-identifiable layer of dead scaffolding from the recently-removed embedded ACP agent and chat panel. The single dominant theme is **dead code**: entire method clusters (streaming, user-message highlighting, `is_primary`/`set_primary`, and a handful of unused `pub` entry points) survive only because this is a binary crate where `pub` suppresses the `dead_code` lint. These dead fields also leave permanently-false branches wired into the per-frame render path, so removing them both shrinks the 5,200-line `editor/mod.rs` and simplifies hot code. The second theme is **oversized god functions**: `editor/mod.rs::render` (~570 lines) and `line.rs::RenderOnce::render` (~725 lines) each interleave many unrelated concerns and already show copy-paste drift. The third theme is a cluster of genuine **correctness smells** — multibyte-unsafe vertical cursor motion, a binary-search overlap bug, a swallowed save-mtime that defeats the self-save reload guard, and an `HttpClient` that silently drops method/headers/body.

The top three things worth doing, in order: (1) delete the ACP/chat dead-code clusters and their now-unreachable render branches — this is low-risk, high-leverage cleanup that also de-noises everything else; (2) fix the four correctness smells, especially `cursor.rs::move_up/move_down` (panic risk on multibyte text) and `styles_in_range` (dropped overlapping styles); (3) decompose the two render god-functions and consolidate their duplicated spacer/issue-item/content-range logic. Doing (1) first makes (3) materially smaller.

## Performance

- **`detect_links` + double HashMap clone run every render frame** (`src/editor/mod.rs:3568` / `3574`, medium) — `render` runs on every `cx.notify` (hover, cursor blink, selection, scroll), and unconditionally calls `detect_links`, which takes a fresh snapshot, allocates two HashMaps, and slices every visible line into an owned `String` for regex scanning — reproducing an identical result when nothing changed. Then `3574-3575` deep-clone both maps into `self` while the originals move into the render closure, so the maps are materialized twice per frame. **Fix:** cache the detection result keyed by `(buffer version, first_visible_line, last_visible_line)` and recompute only on change; share one allocation via `Rc` between `self` and the closure instead of cloning; only re-fire `spawn_*_validation` when the set actually changes.
- **`parse_continuation` reparses per blockquote line every frame** (`src/marker.rs:953`, medium) — `RenderSnapshot::line_markers` has no caching and runs per visible line; any line whose marker text contains `>` calls `parse_continuation`, which builds a new tree-sitter `Tree` just to split a short prefix like `"> > "`. **Fix:** replace with a direct byte scan (emit a `BlockQuote` marker per `>` consuming an optional space, `Indent` for leading whitespace); this also removes the only caller of `parse_continuation`, which can then be deleted.
- **`normalize_ordered_lists` forces a second full non-incremental reparse per renumbering edit** (`src/buffer.rs:317`, medium) — `apply_edit` already reparses incrementally at `280`; when list numbering changes, `normalize_ordered_lists` mutates the rope without informing tree-sitter and reparses the whole document with `parse_rope(&self.text, None)`, discarding incrementality, then runs a full `update_caches`. **Fix:** build an `InputEdit` per digit correction, call `tree.edit`, and pass `self.tree.as_ref()` so the reparse stays incremental (or fold normalization into `apply_edit`'s single parse).
- **`line_markers` recomputed twice per rendered line** (`src/buffer.rs:92`, low) — `build_line` computes `snap.line_markers(line_idx)` then calls `inline_styles_for_line`, whose body recomputes `line_markers` for checkbox styling (same double-compute at `editor/mod.rs:1851`+`1861`). **Fix:** let `inline_styles_for_line` accept the already-computed `&LineMarkers` (see the RenderSnapshot/BufferContent dedup in Refactoring).
- **`propagate_checkbox_after_edit` walks the tree on every keystroke in checkbox-free docs** (`src/editor/mod.rs:1456`, low) — runs on every insert/delete; for the common prose line with no checkbox it still calls `find_parent_checkbox`/`find_sibling_checkboxes` (each a `descendant_for_byte_range` plus ancestor/child walk), up to twice due to the cursor-1 retry and sibling re-check. **Fix:** early-out if the cursor node has no enclosing `list_item`; avoid recomputing `find_sibling_checkboxes` twice.
- **`marker_range`/`prefix_marker_range` allocate a throwaway Vec to read first+last** (`src/marker.rs:113`, low) — collects filtered markers into a `Vec<&Marker>` only to call `.first()`/`.last()`, on the per-line render path. **Fix:** single-pass iterator peeking first, then `last().unwrap_or(first)` for the end; apply to both.
- **`display_heading_level()` re-scans markers per span** (`src/line.rs:855`, low) — called inside the per-style-boundary loop though the result is loop-invariant. **Fix:** hoist `let is_heading = self.display_heading_level().is_some();` above the loop.
- **Mouse-move handler computes visual index + buffer offset twice while dragging** (`src/line.rs:1796`, low) — the drag branch computes `visual_index`/`buffer_offset` (incl. the collapsed-region shaping path) and then unconditionally recomputes both at `1843`/`1853` for hover. **Fix:** compute `visual_index` once; reuse the drag's `buffer_offset` for hover checks.
- **Per-edit `String` alloc to test shortcut-link checkbox** (`src/inline.rs:823`, low) — `extract_link_region` slices the rope to a `String` for every `shortcut_link` node just to compare against `"[ ]"`/`"[x]"`/`"[X]"`, on the every-keystroke `extract_all_inline_styles` path. **Fix:** guard on `full_end - full_start == 3` and compare the three bytes directly.
- **Diff base re-normalized every recompute** (`src/diff.rs:128`, low) — `compute_line_hunks` re-runs `normalize_for_diff` + `.lines().collect()` on the unchanging HEAD base each time. (The larger cost is the `base_snapshot.clone()` at `editor/mod.rs:1806`.) **Fix:** cache the normalized base (and/or interned tokens) in `head_base`; consider avoiding the full snapshot clone.
- **Per-line `DiffState` accessors linearly rescan all hunks** (`src/diff.rs:75`, low) — `is_addition`, `new_inline_changes`, `ghost_lines_before` (and `old_inline_changes` per ghost line) each iterate the full hunks vec, called per visible line → O(visible × hunks). **Fix:** precompute a per-new-line index and a `new_lines.start → old_lines` map in `DiffState::compute` for O(1) queries.

## Correctness smells

- **`move_up`/`move_down` carry a byte column across lines (multibyte-unsafe)** (`src/cursor.rs:107`, medium) — vertical motion computes `column = offset - line_start` in bytes and reapplies it as `target_line_start + column.min(target_line_len)`, also in bytes, so it can land mid-codepoint on a line with multibyte content (e.g. byte col 1 onto a line starting with `"é"`), risking downstream rope panics. `move_left`/`move_right` correctly go through `char_to_byte`. Reachable from production (`editor/mod.rs:177-184`, `3086-3087`, `4059-4061`). **Fix:** track a char column: convert offset→char index within the line, clamp against the target line's char length, map back via `char_to_byte` so the result is always a boundary.
- **`styles_in_range` binary search can miss an enclosing/overlapping region** (`src/inline.rs:920`, medium) — `binary_search_by_key` on `full_range.start` backs up at most one index (only on the `Err` path), assuming at most one preceding region overlaps `range.start`. With nested regions or an inline style spanning a soft line break, an enclosing region is silently dropped (e.g. styles `[A 0..50, B 10..20]`, query `15..16` → scans from B, drops A). Reachable via `inline_styles_for_line` when an emphasis/link node spans a soft break into the queried line. **Fix:** after locating `start_idx`, walk backward while `styles[i-1].full_range.end > range.start` (or drop the micro-opt for a linear scan with early break once `full_range.start >= range.end`).
- **`save()` forgets to record `last_save_mtime`, defeating the self-save reload guard** (`src/editor/mod.rs:3369`, medium) — `reload_file` skips self-triggered reloads by comparing mtime against `last_save_mtime`, but that field is only updated in the autosave branch of `sync_list_state` (`2357`). A manual Ctrl+S writes the file without updating it, so the watcher fires and `reload_file` re-reads and calls `refresh_git_base` (full HEAD reload + diff recompute) for a change nothing external made. Bookkeeping is also split across two sites, and `save` writes `FileInfo::global(cx).path` while the autosave capture reads `self.file_path`. **Fix:** record `last_save_mtime` inside `save()` right after the successful `write`, using the path actually written; drop the duplicate capture in the autosave branch.
- **`HttpClient::send` hardcodes GET, dropping method/headers/body** (`src/http.rs:53`, medium) — the sole global http client destructures `let (parts, _body) = req.into_parts();`, discards the body, ignores `parts.method`, drops `parts.headers`, and issues `client.get(&uri)`. Works today only because remote-image fetches are header-less GETs; any non-GET or header-dependent request (Range/Accept/Authorization, conditional redirects) silently misbehaves with no error. **Fix:** `client.request(parts.method, &uri)`, copy `parts.headers`, forward the body bytes.
- **`graphql()` logs errors but still returns partial data** (`src/github.rs:388`, low) — when `result.errors` is non-empty it only `eprintln!`s (invisible in a GUI) and returns `result.data` anyway, so a partially-failed query is treated as success and transport vs GraphQL failure are indistinguishable. **Fix:** return `None`/`Result` when `errors` is non-empty; consider surfacing failures to the UI.
- **Debug `eprintln!` in the hot per-line list callback** (`src/line.rs:3736` [editor/mod.rs list callback], low) — the `[writ] list callback: ix .. >= line_count ..` print in the hottest render path can spam stderr once per out-of-range line per frame on a transient snapshot/list desync. **Fix:** drop it (keep the guarded early `return`) or gate a single `debug_assert!`/tracing call behind a debug build.
- **Title bar panics when the path has no final component** (`src/title_bar.rs:40`, low) — `file_info.path.file_name().expect("file name")` panics for paths ending in `/`, `..`, or a root, crashing the whole UI render. **Fix:** `path.file_name().map(|n| n.display().to_string()).unwrap_or_else(|| "untitled".into())`.

## Notes

**Sequencing.** Do the dead-code deletions (Dead code section, roadmap #1 and #6) before the render decompositions (#8, #9). A large fraction of `editor/mod.rs::render`'s branching and per-frame work is the streaming/user-message machinery; removing it first means the extraction targets (`user_message_bg`, the `is_user_message`/`streaming_mode` branches, the always-empty clone at `3724`) simply disappear rather than getting carried into new helpers.

**`editor/mod.rs` decomposition strategy.** The file is ~5,200 lines and mixes three separable subsystems: (a) view-only diff editing, (b) the GitHub ref/autocomplete network layer (~`1811-3057`), and (c) render orchestration. Recommended order: (1) delete dead clusters; (2) lift the GitHub subsystem into `editor/github.rs` behind a narrow `update-on-cursor` + `render_popups` interface, which also naturally homes the duplicated issue-item renderer and the detection-cache work (roadmap #7); (3) split `render` into named helpers (`update_status_bar`, `refresh_link_detection`, `manage_cursor_scroll`, `build_line_theme`, `build_line_item`) leaving render as a short orchestration + list-assembly body. Group the diff/`LineTheme` color values into a small render-context struct passed to the per-line builder so the closure stops capturing a dozen locals.

**Cross-cutting duplication.** Several findings are the same drift hazard viewed from different files: `line_markers` is duplicated between `RenderSnapshot`/`BufferContent` *and* recomputed inside `inline_styles_for_line`; the content-range logic exists in three places in `line.rs`; the issue-item renderer and the GraphQL fragment each exist in multiple copies. Fixing the `line_markers` dedup (buffer.rs) and threading precomputed markers through unlocks the per-line double-compute perf fix at the same time — do them together.

**Line::new ergonomics.** The 15-positional-arg constructor underlies both the issue-item duplication and its own inelegance finding; introducing the builder is a prerequisite that makes the shared `render_issue_line` helper clean rather than another 15-arg forwarder.
